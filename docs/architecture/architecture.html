APA — how the CRM is built

The technical companion to the product plan: the layers, the lead flow, and every table, in plain English.

01Overview

This is a Next.js (App Router) app deployed on Vercel, backed by a Supabase Postgres database, with Resend for email. It has two surfaces: a public marketing site at www.apahelpdesk.com.au that captures leads, and an /admin CRM where those leads get worked. /admin starts open and unprotected, and gets locked down with Supabase Auth later in the build.

02How the pieces fit

Next.js — App Router

Renders the public site and /admin. Server code handles form submissions and all database reads and writes. Nothing talks to the database from the browser.

Vercel

Hosts and deploys the app. Environment variables hold every secret. A push deploys — there is no manual deploy step.

Supabase — Postgres

The database. Accessed server-side only, using the service key. Secrets never reach the browser.

Resend

Sends the confirmation email when a lead comes in. Wired in Build 2, once the sending domain apahelpdesk.com.au is verified.

Environment variables

VariableWhat it’s for
NEXT_PUBLIC_SUPABASE_URL The address of the Supabase project. Safe in the browser.
NEXT_PUBLIC_SUPABASE_ANON_KEY The public key. Safe in the browser; can only do what row-level security allows.
SUPABASE_SERVICE_ROLE_KEY The full-access key. Server-side only — never sent to the browser.
RESEND_API_KEY Lets the server send the confirmation email. Server-side only.
NEXT_PUBLIC_SITE_URL The live domain, used to build email links and redirects: https://www.apahelpdesk.com.au

03The lead flow

One inquiry, traced end to end.

  1. A visitor fills in the form on the public site and picks a type: helpdesk, membership or training.
  2. The server upserts a People row by email — if that address has written before, it reuses the existing person rather than creating a second one.
  3. The server creates a linked Contacts row in status new_lead, carrying the type, subject and message.
  4. (Build 2) Resend sends the sender a confirmation email from apahelpdesk.com.au, so they know it landed.
  5. The operator sees the lead in /admin, newest first, and works it — a valid helpdesk inquiry goes to the Help Desk queue with no triage guess in front of it.
  6. Every time the status moves, one activity_log row is written, recording what it moved from, what it moved to, and who moved it.
